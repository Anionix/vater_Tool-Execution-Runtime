# ローカルのウェブ診断入口

対象は、公式の標準入出力クライアントを使わずに手元で計算と状態照会を試したい開発者。ネットワーク越しの運用や永続化を前提としない、読み取り専用ツール（初期構成では加算）の診断である。

Python 3.13 の固定環境で依存関係を復元し、プロジェクトをインストールする。ホストが英数字32文字以上のランダムな値を生成して環境変数 `VATER_LOCAL_HTTP_TOKEN` に設定し、`python -m verified_execution.http_local` で起動する。待受先は `127.0.0.1:8765` 固定。利用者の身元は、ホストが発行する単一のローカル資格情報で確認し、要求本文の自称主体を受け付けない。遠隔公開には別途、暗号化通信、利用者別の認証と権限、運用設計の追加が必要。

| 操作 | 動作 |
| --- | --- |
| `POST /tools/{name}/jobs` | ホストが公開を選んだ読み取り専用ツールを名前で指定して仕事を受け付ける。`Authorization: Bearer <token>` と `Content-Type: application/json` を送り、そのツールの入力スキーマに沿った本文を渡す。受理すると仕事の識別子を返す。公開されていない名前は 404 `UNKNOWN_TOOL` |
| `POST /jobs` | 版1の互換ルート。既定ツール（`checked_add` を公開している場合はそれ）を実行し、`POST /tools/checked_add/jobs` と同じ結果を返す |
| `GET /jobs/{job_id}` | 準備・実行・完了・失敗・取消しの状態と、確定済みの結果を返す |
| `DELETE /jobs/{job_id}` | 準備済みの仕事を取り消す。実行中や完了済みは拒否する |
| `GET /openapi.json` | 同じルート定義から生成した OpenAPI 3.1 の記述を返す |

公開するツールは `create_app(token, authority, registry=..., tools=[...])` でホストが選ぶ。省略すると登録済みの読み取り専用ツールをすべて公開する。入力スキーマ・引数の検査・権限・結果の確認は共通の `ToolRuntime` が担い、この入口は資格情報・媒体の種類・本文の大きさ・JSONの解釈・仕事の管理だけを持つ。OpenAPI にはツールごとの具体的なパスと入力スキーマを載せる。権限はツールごとに判定し、許可のないツールは 403 `NOT_AUTHORIZED`。資格情報がない要求には、ツール名の有無にかかわらず 401 を返す。`python -m verified_execution.http_local` は最小構成の `checked_add` だけを公開する。

受信本文は4,096バイト、深さ32に制限する。仕事は単一の枠で実行し、最大64件をメモリに保持する。上限時は古い終了済みの仕事を除き、すべて未終了なら新規受付を拒否する。受理済みの仕事は問い合わせ接続が切れても継続し、切断を理由に再実行しない。新しい `POST` は別の仕事なので、結果照会には受理時の識別子を使う。プロセス再起動で記録は消える。

変換の根拠は [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1)。ローカル実接続の検査は `python -m pytest tests/test_http_local.py`。
